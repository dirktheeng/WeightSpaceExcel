- Design choice before any weights (decision K1, log/WORKLOG.md): one network per step for the kernel. Phase dispatch inside one network (ONEHOT(PC) plus vector MUX) would make each network the sum of all its phases; routing by `next` is free, so every kernel network does exactly one step and PC is left at 0. Output = small dense "head" over a gathered slice of the input + PASS slices of every untouched word, so most networks have 14 to 70 parameters.
- Wrote boot.wt, trap.wt, ret.wt, halt_ok.wt by hand. Caught one error while reviewing boot.wt before any run: the PC row had weight -9 on o_9 with bias 1, which would leave PC = 1 entering the main loop; corrected to -10 (PC + 1 - 10 = 0).
- Cell store design (K2): get and set share the hash and probe networks; T1 selects the mode, so CELL_SET is not a nested call around CELL_GET (no return stack push). The probe step does the first write itself (A.TAG on a hit, KEY on an empty slot), saving one step per set.
- Wrote cs_hash.wt, cs_probe.wt and the chain cs_ltag .. cs_wcalc. Reasoned every probe field row against the five outcomes in a table (found/get, found/set, empty/set, empty/get, other key): next = 17 + f + 5 fm - 17 e + 20 em + rN gives 18, 23, 20, LR, 17; mem_op = 1 + fm + 2 em - e gives 1, 2, 2, 0, 1; addr = rA - 7 f - 8 e + 8 - 2^19 ow gives P0 + 1, P0 + 1, P0, 0, P0 + 8 (or wrapped).

Cause: the address row used 8 floor(t / 2^16), the quotient, instead of the remainder t - 65536 floor(t / 2^16). Fixed by hand: addr row and P0 row = 8 t - 524288 r + 524288 g + 65536.

- Key design idea (decision FD-1 below): floor division by a constant d of an integer x is done as q = ROUND(c x + b) with c close to 1/d and b close to -0.5 + 0.5/d. For integer x, x/d has fractional part in [0, (d-1)/d], so c x + b lies at least 0.5/d away from every half integer and ROUND gives floor(x/d). Constants need only about 8 significant digits for the ranges used (|x| < 4e6), so all constants can be worked out by hand with long division, and each floor costs one dense row plus the 2-row ROUND.

- Design choice: the parser is a leaf subroutine that keeps every word but A and STATUS. Reason: dt_abi's reference loop keeps its slots in T3..T8, N1, T2 and the evaluator path keeps everything; a parser needs about 22 state words. So dv_ent spills words 8..39 (one block write of 32 words, RSP += 32), the loop and finisher use words 12..39 freely, and dv_rest (block consumer, 97 inputs) restores them and returns to the spilled link. Block payload rule T4 forces the spill into its own network (output 96 words), and the restore read into a consumer: 4 ids (354 dv_ent, 355 dv_loop, 356 dv_fin, 357 dv_rest).
- One character per step: dv_loop re-reads the packed word of character i each step (word address a and j = i mod 3 kept as state; unpack by two exact power-of-two FLOORs) and runs one token-machine update: digits accumulate into acc; a non-digit ends a number, which goes to the time fields when the terminator is ':' or a ':' was seen, else to the date fields; letters accumulate a key 1024 c1 + 32 c2 + c3 of the first three letters (A = 1, case folded) matched by 16 IS_K pairs against the 12 month keys and A, AM, P, PM. A virtual space after the last character flushes the last token, then dv_fin.
- dv_fin: date forms m/d/y, y/m/d (first field > 31), m/yyyy (second field > 31), d-mmm-y / mmm d y (month name with two numbers), mmm yyyy (one number > 31); 2-digit years 0..29 -> 20xx, 30..99 -> 19xx; years 100..1899 and > 9999 rejected; day checked against the month length with Excel's 1900 leap day; time h:mm[:ss] with optional AM/PM, or "h AM"; minutes and seconds < 60; hours <= 12 with AM/PM, < 10000 without. It then calls dt_time (time fraction, correctly rounded, wraps at 24 h) and dt_date (serial), and picks the result by mode.

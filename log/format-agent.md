## 2026-11-06, start
- Read AGENT_BRIEF, GOAL, docs/*, harness/FORMAT.md, encodings/*, weights/prim/CONVENTIONS.md, weights/eval/README.md and format.md, weights/ui/fnum.md and glyph.md, the tail of WORKLOG.
- encodings/functions.md (ABI) does not exist yet, so the engine is written as subroutine networks with explicit register inputs and outputs (below); it will be wrapped once the ABI appears.
- Existing number-to-text code: ev_fmt0/ev_fmt_emit (eval, General without width, range 1e-10..1e21) and ui/fnum (11 characters, no scientific). Both are limited; the format engine replaces them for display and TEXT.
- Plan (decision F1 in WORKLOG): one shared numeric core for General and custom codes.
  1. fx_dec: |x| -> sign s, decimal exponent e, 15-digit mantissa m in [1e14, 1e15) (Excel's 15 significant digits), in one forward pass, no N x N one-hot matrices (candidate-and-gate trick, notes in fx_dec.md).
  2. fx_rnd: round m half up (decimal, exact integer arithmetic) to the digits the section shows, giving a left-aligned digit stream M and an integer digit count R.
  3. emitter: walks a compiled token list (one token word: code * 65536 + argument) and writes one character per step to an unpacked buffer, peeling digits from M (d = floor(M / 1e14), M = 10 (M - 1e14 d)).
  4. finisher: #### overflow, fill character, pack into a heap string.
  5. General = a planner that picks fixed or scientific and the decimals from the width, then runs the emitter on two fixed token records ("0" conditional point, 10 '#' fraction digits; and the same plus E+00).
  6. Custom codes: a compiler network family turns a code string into a compiled record (sections, conditions, colors, counts, tokens), cached in a format table.

## 2026-11-06, numeric core
- fx_dec (192) written by hand: coarse bank of 39 candidates c_g = |x| 10^(320 - 16 g) with gates [c_g >= 1][c_(g+1) < 1] (exact complements, one gate is 1), then a fine bank of 17 candidates a1 10^(14 - j) gated by [cand_j > L][cand_(j+1) <= L], L = 99999999999999.5, using L' = nextup(L) = 99999999999999.515625 (spacing 2^-6 in [2^46, 2^47)). No N x N one-hot matrices. Candidates for |x| >= 1 are formed from |x| and for |x| < 1 from |x| [|x| < 1], so no candidate overflows (V1). Forward pass 1: all 15 cases correct (1, -123.456, 0.001, 1e300, 1e-300, 1/3, 2/3, max double, 0, 9.999999999999999, 1e16, 12345678901234567890, 99999999999999.5, 5e-5, -0.1) plus the scale input.
- fx_rnd (193): decimal half-up rounding of m at q = e + 1 + k (fixed) or nint + k (scientific) significant digits, exact with D = 10^(15 - q) selected by a [q >= i][q < i + 1] mul one-hot, q0 = ROUND((m + D/2) / D) corrected by the sign of the exact residual. Alignment shift 10^-(max(-e-1, 0)) for values below 1. Carry (M = 1e15) bumps R (fixed) or X (scientific). Forward pass 1 failed my own review before running: in scientific mode the carry bumped R; fixed by gating the carry with (1 - sci) (tail retyped; I spliced my typed tail into the file with a short python text edit, no values computed). Then 16 cases correct, including 1.005 -> 1.01 (Excel's 15-digit-then-round behaviour), 0.96 -> 1.0, 0.5 -> 1, -2.5 -> 3 (half away from zero).
- Emitter: fx_fetch (194), fx_end (200), fx_lit (201), fx_int (202), fx_point (203), fx_frac (205). Token word = arg + 65536 code + 2^20 nc; nc (code of the next token) lets fx_fetch route straight to the executor (next = 200 + NC), so each character costs 2 steps (read token, write char) and each executor handles one code only.

# Weight block notes: weights/ui/glyph.wt (id 129, text run draw and measure, font ROM)

Hand-written, including the font. Not generated. No font file was read; every glyph is an original 12-row bitmap drawn to approximate the proportions of Excel's default sans font at 11 pt, 100 percent zoom. Log: log/ui-agent.md; decisions U1, U4 (font format).

**Computes.** Draws the 0-terminated string at P0 (one UTF-16 unit per word) with its pen at T0 and its top at T1, in colour T2, clipped at x <= T3. In measure mode (T8 = 1) it only advances the pen, at 1 step per character. It returns to (LR, LP) with T0 = the final pen.

**Font ROM (v32, dense 96 x 13).** Row c is glyph code 32 + c (row 95 is the missing-glyph box, used for code 127 and every unsupported unit). Columns 0..11 are glyph rows 0..11; each is a decimal number whose digits are the pixels left to right, written with exactly ADV digits. Column 12 holds ADV * 10^12 and is multiplied by a constant 1 input. Metrics: row 8 is the baseline row; cap height 9 (rows 0..8); x height 7 (rows 2..8); descenders rows 9..11. The first column of every glyph is blank (the left bearing). Advances: digits 7, most capitals 7 to 9, M 11, W 12, i/l/I 3, space 3.

**Derivation.** Glyph row one-hot e_j = u_j w_(j+1) (u = [gy >= j], w = [gy < j]; one mul layer instead of a difference matrix). Char one-hot is the same over c2, where c2 is the code clamped into 32..127 (codes below 32 and above 127 map to 127). Each step V = W [e, 1] gives every glyph's current row plus 10^12 ADV, and V . onehot(c) picks one; exact because there is one nonzero product. ADV = ROUND(V 10^-12), since R < 1.2e11 makes the fraction < 0.12. R = V - 10^12 ADV is exact. The pixel digit is d = r - 10 ROUND(r/10), exact because every digit is 0 or 1, so r/10 has fraction 0 or 0.1. Pixels go right to left, k = 0..ADV-1, at x = pen + ADV - 1 - k. The last step of a glyph (k = ADV - 1, gy = 11) is always the blank bearing pixel of the descender row, so that step reads the next character instead of writing. The character arrives in input word 0 on the following step and is latched into T4 (c_eff = first ? x0 : c). Entry with k = -1 makes a fetch-only step.

**Phases (all in one network, selected by indicators).** fr fetch (k < 0); first (k = 0, gy = 0) uses x0 as the character; term (first AND (c = 0 OR pen >= clipR)) returns; ms (first AND measure) adds ADV and reads the next unit; end of glyph adds ADV and reads; otherwise draw (write if d = 1 and x <= clipR).

**Limits.** One size and one style only (no bold or italic). Ink only, with no anti-aliasing. Text is clipped on the right only; a right-aligned string wider than its box is pushed to start at the box's left edge and then clipped (Excel would show ### for numbers). Codes above 127 draw as a box.
**Parameters.** 3,612 (hand count; 1,248 of them are the font table). **Steps.** 12 ADV per drawn character (84 for a digit), plus 1 fetch and 1 return; measure is 1 step per character plus 2.
**Multi-role weights.** The font dense (v32) carries two fields in one number: R occupies values below 10^12 and ADV is the multiple of 10^12. They separate exactly because R < 0.12 10^12. Covered by test_glyph_measure_and_draw.

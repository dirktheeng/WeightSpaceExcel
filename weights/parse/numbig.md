# Note: weights/parse/numbig.wt (id 123)
Hand-written. Not generated. Shared conventions, register map and limits: weights/parse/README.md. Log: log/parse-agent.md 2026-11-06 (session 2); decisions P6 to P10 in log/WORKLOG.md.

**Role.** Decimal to double when |E10| > 22 (numconv routes here with TK 11 and the lnum registers unchanged). Returns to (X6, X7) with TV and TK like numconv.
**Phases (TK as phase, a deliberate second role).** TK 11 = INIT, TK 12 = LOOP; on return TK is 1 (number) or 11 (out of range). TK is the in-flight token's kind, owned by this token during conversion, so no other reader sees 12.
**INIT.** E10, k = |E10|, e = SIG - 1 + E10 (decimal exponent of the leading digit), M15 = M 10^(15 - SIG) (thermometer u1..u15 on SIG; F row written over thresholds, coefficients 10^14, -9 10^13, ..., -9, exact integers; one mul). OVF = step(eA + eB + big + 2 nz - 3.5) = nz and (e >= 309 or (e = 308 and M15 >= 179769313486232)). ZERO = step(eC + eD + small - 2 nz + 0.5) = M = 0 or e <= -309 or (e = -308 and M15 <= 222507385850720). The two 15-digit bounds are the largest double 1.7976931348623157e308 and 2^-1022 = 2.2250738585072014e-308 truncated to 15 digits. Otherwise the loop starts with h = 2^-512, l = 0, y = 2^512, rem = k, neg = [E10 < 0] in X1..X5.
**LOOP.** Thermometer t1..t23 on rem, one-hot h0..h22 plus t23, ROM D = 10^min(rem, 22) (exact) and Dinv = fl(10^-min(rem, 22)) with one nonzero term per row. (h, l) times D: p = fl(h D), err by Dekker split (2^27 + 1) and TwoProduct (v42..v60, as numconv), t = err + fl(l D), hn = p + t, ln = t - (hn - p) (FastTwoSum). y' = fl(y Dinv), rem' = rem - min(rem, 22). When rem = 0 the same multiplier runs once more with D = M (positive: TV = hn 2^512) or D = q0 = fl(M y) (negative: r = (M - p) - t, TV = (q0 + fl(r y)) 2^-512); gR, gP, gN select D by mul gates.
**Why 2^-512.** P' = 10^k 2^-512 stays inside [1e-132, 1e168] for every k this network accepts, so the Dekker split never overflows and the final scaling by 2^512 or 2^-512 is exact (normal results only, which OVF and ZERO guarantee). Both constants are built in the pass by squaring [65536, 2^-16] five times (exact).
**Accuracy (argued, not proven).** The double-double P' has relative error about 15 * 2^-105; the positive result is one rounding of p + t; the negative result is a residual-corrected quotient with y accurate to about 2^-48, so the error before the last rounding is about 2^-96 relative. Correct rounding fails only within that distance of a halfway case. Every case tried rounds like the Python literal (log).
**Finite everywhere (V1).** INIT-mode values flowing through the loop block (SIG, FRAC, DROP, EXPV in the h, l, y, rem slots) stay finite; r and hn are gated by mul before the scaling multiplies.
**Steps.** 1 (INIT) + ceil(k / 22) + 1. **Params.** 1,517. **Multi-role weights.** TK as phase (above); X1..X5 hold SIG..ESGN in INIT and h, l, y, rem, neg in LOOP (exclusive by TK).
